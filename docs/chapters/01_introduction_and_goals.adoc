== Introduction and Goals

AsciiDoc is a lightweight markup language for technical documentation.
Editor support lags behind Markdown.
asciidoc-lsp is a language server for AsciiDoc written in Rust.
It parses with tree-sitter grammars and provides document symbols, go to definition, references, rename, completion, diagnostics, and hover.

[[project-goals]]
=== Project Goals

. Go to definition for cross-references, includes, anchors, and attributes across multi-file AsciiDoc projects.
. Diagnostics for broken references, missing includes, and undefined attributes while you edit.
. Awareness of workspace-wide structure: include trees, shared attributes, and references between documents.

=== Stakeholders

[cols="1,2,2", options="header"]
|===
| Role | Description | Expectations

| Technical Writers
| Authors who write AsciiDoc documentation daily
| Fast navigation, reliable diagnostics, include resolution

| Software Developers
| Developers who maintain architecture docs (arc42, ADRs)
| Go-to-definition for xrefs, workspace-wide symbol search

| Neovim Users
| Users who prefer terminal-based editors
| Straightforward LSP setup

| Plugin Maintainers
| Developers of editor integrations
| Stable LSP protocol adherence, documented capabilities
|===

=== Quality Goals

[cols="1,2", options="header"]
|===
| Quality Goal | Description

| Correctness
| Cross-references and include paths resolve as in Asciidoctor, including attribute-based paths and implicit section IDs.

| Fault Tolerance
| The server stays operational when documents contain syntax errors. Partial results are preferred over crashes.
|===
