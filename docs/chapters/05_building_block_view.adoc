== Building Block View

[[building-blocks]]
This section describes the major building blocks of the asciidoc-lsp system and their responsibilities.
The architecture follows a layered approach where each layer has a clear responsibility and communicates with adjacent layers through well-defined interfaces.

image::building-block-view.puml[Building Block View]

The system consists of three primary layers: the Transport Layer handles LSP protocol communication, the Workspace Manager maintains the state of all open documents and their relationships, and the Semantic Layer provides the intelligence behind LSP features like go-to-definition and diagnostics.

=== Layer Overview

The Transport Layer sits at the boundary of the system, receiving JSON-RPC messages from the editor and dispatching them to the appropriate handlers.
The Workspace Manager maintains an in-memory representation of the entire documentation workspace, tracking open files, include relationships, and parsed syntax trees.
The Semantic Layer consumes the parsed trees and workspace state to provide the actual LSP feature implementations.

Each layer is designed to be independently testable.
The Transport Layer can be tested with mock LSP clients, the Workspace Manager with file system fixtures, and the Semantic Layer with pre-constructed syntax trees.
